# CrabDesk 20260924.01

本次更新基于 `v20260922.01`，修复桌面按「创建日期」排序时会被打乱的问题，并改进批量删除失败时的反馈。

## 桌面排序

### 支持「创建日期」排序

- 此前只有名称、大小、类型、修改时间四种排序会被识别。当桌面被设为按**创建日期**排序时，这一项无法识别，排序方式会退回名称：桌面看起来被静默重排成 A-Z。
- 典型触发场景：把新建的文件拖到桌面上某个位置，随后的一次重绘就会把整个桌面按名称重新排列。
- 现在「创建日期」作为独立的排序方式处理，取值范围是文件的**创建时间**，与「修改时间」分开——编辑文件只会改变修改时间，两种排序结果确实不同。

### 排序状态不再被临时读数覆盖

- Explorer 在应用排序或视图变化时，可能短暂返回空的排序信息。此前这种临时读数会被当作「按名称排序」，从而把已知的「创建日期」排序覆盖掉，并连带清空已保存的图标布局。
- 现在只有确认有效的排序读数才会被采纳；临时的空读数不再降级已知排序，也不会再清空已保存的图标布局。
- 已知的排序方式会随布局一起保存，下次启动时如果 Explorer 暂时读不到排序，会沿用上次保存的排序方式，而不是默认回名称。

### 显式刷新时的排序回退

- 右键菜单「刷新」或 F5 触发的重排，会按 Explorer 当前的排序方式执行。当 Explorer 完全读不到排序信息时，此前会退回名称排序；现在改为按**创建日期**升序排列，使刷新结果与桌面被设为按创建时间排序时一致。

### 右键菜单新增「刷新图标」

- 桌面右键菜单新增「刷新图标」项，与 F5 走同一条刷新流程，行为一致。

## 桌面删除

- 修复批量删除时，只要有**一个文件被占用**（例如文档仍在编辑器中打开），整个删除就中断、其余选中项都不会被删除的问题。现在每个项目独立处理，被占用的项目不会影响其他项目。
- 删除部分失败时会明确提示：列出已删除数量、失败数量与失败原因（文件名 + 错误信息），不再只在全部失败时才有反馈。
- 属于系统桌面项目或只读映射目录、无法删除的项目会被跳过并单独说明。
- 修复删除失败的项目仍被当作已删除、导致其图标格子被清空的问题——删不掉的文件仍占用桌面位置，不会凭空消失。
- 同一文件被重复选中时只删除一次。

## 维护

- 移除了两个只能在有桌面会话且有已发布版本的机器上运行的 GitHub 验证脚本（`verify-github-release.ps1`、`verify-github-updates.ps1`）。它们的引用此前仍然留在发布策略检查中，导致 CI 的发布策略步骤失败。相关校验已并入发布策略检查，正式发布的人工验收步骤改为使用 `gh release download`、SHA-256 与签名核对命令。
