# CrabDesk 20260905.01

2026 年 9 月 5 日测试版，对比上一版本 `v20260902.01`。本次更新修复在桌面粘贴文件后整个系统输入卡住数秒的问题，把粘贴、删除、分配盒子等操作的整屏重建改为只刷新受影响的区域，让桌面刷新（右键菜单“刷新”或 F5）按当前排序方式重排图标，并为桌面与盒子加上 Shift 范围选择。

## 刷新与排序

- 桌面刷新后按 Explorer 当前的排序方式重排全部图标：刷新前丢弃已保存的手动网格，每个图标重新按排序属性从第一个空位开始排列，与右键菜单“排序方式”的效果一致。这一轮不写回手动布局，下一次普通重建再把新的单元格持久化。
- 新增 F5 作为刷新入口。桌面处于前台时由低级键盘钩子接管，与右键菜单“刷新”共用同一条队列，因此去抖、合并与重排逻辑不会在两个入口之间产生差异；按住 F5 只会合并成一次重建。
- F5 是唯一不需要选中项的桌面按键，钩子侧的廉价判定与 UI 线程侧的精确校验都显式放行它，而不是落到“是否有选中项”的默认判断。删除正在进行时 F5 仍然交回 Explorer。
- 只有显式刷新和原生“排序方式”命令会重排。新建文件、重命名、粘贴、显示器变化等自动刷新继续保持用户拖放的位置不变。两个一次性标志相互独立，同一轮消息中同时到达时不会互相吞掉对方的重绘。
- 刷新失败也会清掉重排标志，避免下一次无关的重建把手动布局一并丢弃。
- 注意：显式刷新会丢弃手动布局，多显示器下副屏图标会被拉回主屏，与原有“排序方式”命令的行为一致。

## 选择操作

- 桌面图标与盒子内项目支持 `Shift` + 点击范围选择：从锚点到点击项按各表面自己的阅读顺序整段选中。桌面网格按列优先（先向下再向右），盒子按当前可见布局顺序。
- `Ctrl+Shift` 在已有选择上追加范围，单独 `Shift` 则接管整个桌面选择。普通点击与 `Ctrl` + 点击都会把锚点移到该项，`Shift` 自身不动锚点，因此可以反复 `Shift` + 点击从同一个锚点重新扩展。
- 锚点在使用时才校验：被搜索过滤掉、滚出盒子可视区域、切到别的子标签或换了显示器时，这次 `Shift` + 点击退化为普通点击。清空选择、或选择被另一个表面接管时锚点一并失效。
- 盒子内的范围不跨盒子、不跨子标签。
- 空白处框选时 `Shift` 与 `Ctrl` 一样按追加处理，不会把刚用 `Shift` 建立的范围丢掉。

## 定向刷新

- 粘贴到桌面只重绘新文件占用的图标单元格，不再重建每块显示器的图标层、也不再丢弃已加载的图标位图；若导入的文件被已有归属记录认领，则刷新对应盒子而不是桌面单元格。
- 把桌面项目分配到盒子（拖入、剪切粘贴、批量分配）只刷新目标盒子和被腾空的桌面单元格；导入盒子时若每个文件都成功归属，则只刷新那一个盒子。
- 删除项目（按 `Delete`、拖到回收站、在盒子内删除）只重绘被腾空的图标单元格和受影响的盒子，同样不再整屏重建、不丢弃图标位图。
- 映射文件夹盒子内的删除按路径与删除前的映射快照比对，定位到对应盒子刷新；这类项目不在桌面快照里，此前只能靠整屏重建补画。
- 把外部文件拖到回收站删除时，若这些路径本来就没有任何表面在渲染，则所有显示器与盒子保持原样。
- CrabDesk 自己造成的文件变更不再触发第二次全屏重建：文件系统监视通知到达后先比对新旧快照，只重绘真正增删的桌面单元格与盒子。同一去抖窗口内夹带的其它变更仍会被处理，原地重命名这类无法表达为脏区域的变更继续走整屏重建。
- 自有文件操作的识别窗口从 2 秒放宽到 10 秒，并在每次命中后顺延：复制大批文件会产生一串通知，操作本身可能比初始窗口更久。窗口生效期间跳过 Explorer 宿主探测，避免与 Shell 自己的桌面刷新相撞。
- 定向刷新报告“没有重绘任何区域”时才回退到整屏重建，避免精细路径漏画图标。
- 变更不涉及某块显示器时，该显示器保持当前画面，不再因为空的脏区域而整屏重绘。
- 桌面图标拖入文件夹后的移除刷新修正为按项目键匹配（此前传的是目标路径，从未命中，只能靠后续整屏重建补画）。

## 输入响应

- 修复在桌面粘贴文件后整个系统的鼠标与键盘卡住数秒、桌面无法操作的问题。Windows 把低级输入钩子的回调派到安装它的线程上，并在回调返回前扣着这个输入事件，下面几项共同造成了卡顿。
- 钩子不再安装在 UI 线程，而是跑在自己的 STA 消息循环线程上：CrabDesk 渲染图标层、重新枚举桌面或等待 Explorer 时，不会再阻塞全系统的每一次敲键与鼠标移动。退出时向该线程投递 `WM_QUIT` 结束循环，两个钩子只会被解除一次。
- 钩子回调内加了异常兜底。回调运行在非托管输入派发上，逃出去的异常会直接结束进程；无法归类的消息交回它原本的归属者。
- 钩子里的判定改成只读原子状态：`Ctrl+V` 之前只查剪贴板提供的格式，不再读取剪贴板内容（该读取会跨进程等待剪贴板所有者应答），也不再在钩子上解析粘贴目标盒子与重建盒子几何。精确校验仍在 UI 线程执行命令前重做一次，无目标的按键直接丢弃。
- 钩子可用的盒子命中测试改为纯读取：不再顺带清理高度动画与释放它们的缓存位图，这些属于 UI 线程的副作用。
- 鼠标钩子只对左键按下、右键按下、滚轮做窗口命中测试，指针移动不再付任何代价；普通滚轮（未按 `Ctrl` 且没有拖拽进行中）在命中测试之前就已返回。
- 桌面盒子层与图标层加上 `WS_EX_NOPARENTNOTIFY`：此前每一次按键都会让 USER32 向 Explorer 的桌面窗口链同步投递 `WM_PARENTNOTIFY`，Explorer 忙碌时会把 CrabDesk 自己的输入一起拖住。
- 盒子上的滚轮事件就地标记为已处理，不再由 WinForms 把 `WM_MOUSEWHEEL` 同步转发给 Explorer 父窗口 —— Explorer 正在发布刚粘贴的文件时，这一步可能要等上数秒。
- 剪贴板的读取与清空移到各自的短生命周期 STA 线程：OLE 剪贴板要求单线程单元，而慢的剪贴板所有者从此只会拖慢这一个操作。
- 粘贴操作串行化。UI 线程卡顿恢复后会一次性冲出排队的 `Ctrl+V`，此前会同时启动多个粘贴、各自做一次剪贴板 COM 读取与整轮桌面枚举，把一次卡顿放大成连锁反应；改为排队而不是丢弃，用户按下的每一次粘贴都仍会执行。
- Explorer 宿主探测、桌面视图与图标间距的同步、启动时的首次 Shell 读取都移到线程池执行，UI 线程只负责应用结果；三个宿主句柄一起提交，表面不会观察到半更新的状态。健康检查也不再顺带轮询 Explorer 的自动化视图。
- Explorer 桌面视图（排序、图标尺寸、自动排列）与图标网格间距的读取加了缓存快照。两者都要跨进程问 explorer.exe（间距还带 500 毫秒发送超时），而一次文件操作会让表面重建反复询问，此时 Explorer 恰好在处理同一次变更。渲染路径只读缓存，用于变更检测的调用点仍做实时读；CrabDesk 自己请求 Explorer 改变图标尺寸时主动作废缓存。

## 图标加载

- 桌面图标缓存键加入文件修改时间，文件内容变化后会重新取图，而不是继续显示旧图标。
- 刷新时不再先清空整个图标缓存再重新加载，而是在重建之后剔除已不在画面上的条目，仍在显示的位图保持有效。
- 每块显示器最多同时进行 2 个 Shell 图标读取，避免整屏几百个项目同时发起调用、完成回调淹没 UI 消息队列。
- 图标读取完成时若该项目已不在画面上，结果直接丢弃，不再写入缓存。
- 盒子内的图标读取也移到线程池，不再在 UI 线程上同步调用 Shell。

## 诊断

- 新增 UI 线程看门狗：独立线程按 100 毫秒采样，超过 750 毫秒没有响应即报告卡顿，并给出当时正在执行的工作名称（分派的回调名，或窗口消息号）。它不依赖线程池，因此线程池被打满时仍能报告。
- 派到 UI 线程的运行时回调、定时器回调、以及盒子与图标窗口的消息处理都会留下面包屑；空面包屑意味着 UI 线程阻塞在 CrabDesk 自己调度之外的地方。
- 新增 250 毫秒 UI 心跳，间隔超过 750 毫秒时记录日志，并把延迟拆成“线程池回调间隔”与“回调排队等待 UI 线程的时间”两项 —— 只有后者才说明 UI 线程本身被阻塞。
- 新增分阶段耗时日志：粘贴（剪贴板读取、导入、刷新、归属）、桌面枚举、自动保存、盒子项目刷新、重命名编辑框、Explorer 宿主探测，以及任何超过 100 毫秒的窗口消息。

- 刷新优化新增测试（`DesktopPasteRefreshTests`）：桌面粘贴只走定向刷新、无法匹配的导入路径回退整屏、分配盒子同时刷新盒子与腾空单元格、定向刷新失败时回退、导入盒子的单盒刷新、自身变更的快照比对与整屏回退条件、空脏区域时保持当前画面、被已有归属认领的导入项刷新对应盒子、拖入文件夹按项目键清除单元格。
- 删除刷新新增测试（`DesktopDeleteRefreshTests`）：三个删除入口都改走定向刷新、删除前捕获路径与解析项目键、登记路径抑制监视的二次刷新、归属盒子与桌面单元格分别刷新、映射盒子按路径匹配、没有表面渲染这些路径时不动任何表面、定向刷新失败时回退整屏。
