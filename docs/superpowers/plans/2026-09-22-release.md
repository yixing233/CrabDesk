# CrabDesk v20260922.01 Release Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** 发布可追溯的 v20260922.01 预发布版本，提供准确中文更新说明、安装包与校验附件。

**Architecture:** 使用仓库现有 tag → GitHub Actions Release 流程。先核实与 v20260913.04 的差异、本地测试和发布门槛，再提交代码与独立发布提交，推送 tag；不覆盖旧 release。

**Tech Stack:** .NET 8、WinUI 3、Inno Setup、Native AOT Bootstrapper、GitHub Actions、gh CLI。

---

### Task 1: 核实发布范围
- [ ] 检查 `git status --short` 和 `git diff v20260913.04`，核对用户可见功能。
- [ ] 保留工作区中既有修改；`build/verify-github-release.ps1` 与 `build/verify-github-updates.ps1` 的既有删除不自动纳入本次提交，不恢复用户删除。
- [ ] 审核桌面重连、间距与拖出桌面的实现和测试；源码字符串测试不能当作真实 Explorer 重启回归验证。没有证据不宣称右键菜单故障根治或第三方扩展已被确定为根因。

### Task 2: 更新发布元数据
**Files:** `CHANGELOG.md`, `docs/releases/v20260922.01.md`, `CrabDesk.WinUI/CrabDesk.WinUI.csproj`, `CrabDesk.Bootstrapper/CrabDesk.Bootstrapper.csproj`。
- [ ] 将两个项目的 Version 设为 `20260922.01`，按现有日期规则标为 prerelease。
- [ ] 将当前未发布的 20260919 草稿内容汇总为新版本说明；保留此前已发布版本历史。
- [ ] 使用用户可见措辞描述 AI 工作台、诊断、规则整理、盒子显示、字体、桌面刷新与拖放；测试结果只填写本次实际运行结果。

### Task 3: 补齐附件契约
**Files:** `.github/workflows/release.yml`, `docs/RELEASING.md`。
- [ ] 在 Package release assets 的 `$assets` 列表中加入 `artifacts\installer\CrabDesk-Payload-x64.exe`，让 SHA256SUMS 同时覆盖两个 exe。
- [ ] 在 Create GitHub Release 的 `$arguments` 中加入同一 Payload 路径。
- [ ] 同步发布指引，说明三个附件均自动上传、Setup 为推荐入口、Payload 不负责补装依赖。
- [ ] 运行 `pwsh -File build/verify-release-workflow.ps1`，核查脚本要求后执行相关配置验证。

### Task 4: 本地验证与构建
- [ ] `dotnet test CrabDesk.Tests -c Release`。
- [ ] `dotnet test CrabDesk.WinUI.Tests -c Release`。
- [ ] `dotnet test CrabDesk.Bootstrapper.Tests -c Release`。
- [ ] 读取并执行 `build/assert-release-configuration.ps1 -Version 20260922.01`。
- [ ] 按现有脚本发布到 artifacts，依次执行 publish.ps1、build-installer.ps1、publish-bootstrapper.ps1；注意 publish.ps1 会停止正在运行的 CrabDesk，执行前告知用户。
- [ ] 核实安装器启动、嵌入应用版本、资源文件、桌面接管及图标间距；不将单元测试等同于完整桌面交互验证。

### Task 5: 提交、上传及验证
- [ ] 显式暂存已审核功能文件，提交功能修复；版本和日志另做 `release: v20260922.01` 提交。不得 `git add -A` 混入无关删除。
- [ ] 检查远端 main 最新状态并正常推送（不强推），创建与发布提交一致的 tag，推送 `v20260922.01`。
- [ ] 追踪 Release workflow，收集失败信息后再处理，不能在失败时宣称已发布。
- [ ] `gh release view v20260922.01 --json url,isPrerelease,tagName,assets,body` 核对正文、标记与三个附件。
- [ ] 下载到工作区 `artifacts/release-verification/v20260922.01`，用 SHA256SUMS 核对两个 exe，再核对文件版本与大小。
- [ ] 向用户交付 release 链接、推荐安装包、验证结果以及实际存在的验证限制。
